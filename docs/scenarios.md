# 这套链路能干什么、不能干什么

> 所有判断都基于**实测**，不是「理论上可以」。
> 每条都写明是哪个方向（A=回国 / B=出国）和实测数字。

---

## 先记住一个换算

**B 方向满额约 7.5 Mbps → 一小时 3.4 GB，一天 80 GB。**
**A 方向单流 99 Mbps → 一小时 44 GB。**

所有「能不能」的判断，先过这一关。**带宽不够的，任何优化都救不回来。**

---

## 能做的

### 1. 政务 / 银行 / 票务站点（A 方向，这是它的主场）

| 目标 | 直连 | 走隧道 |
| --- | --- | --- |
| 政务门户（含 JS 挑战） | **11.2 秒超时，打不开** | **0.61 秒** |
| 政务子站（安全监管平台） | 打不开 | **0.26 秒** |
| 企业信息查询 | 1.16 秒 | **0.55 秒** |
| 地方政务 | 打不开 | **0.34 秒** |

**为什么只有它能做**：这类站点对**机房 IP** 有额外风控（验证码、限速、直接拒）。
商业加速器的出口是机房 IP，所以会被拦。住宅 IP 不会。

**这是整套方案唯一不可替代的价值。** 不是省钱，是拿到一个「境内住宅」的出口。

### 2. 视频站 1080p（A 方向）

| 直连 | 走隧道 |
| --- | --- |
| 0.80 秒 | **0.62 秒** |

1080p 需要 5–8 Mbps，A 方向单流 99 Mbps，**余量充足**。4K 需要 20–25 Mbps，
A 方向也够，但要注意对端上传带宽是否被其他程序占用。

### 3. 分区流媒体（B 方向）

1080p 需要 5–8 Mbps，B 方向满额 7.5 Mbps——**刚好够单流，且不能同时干别的**。

住宅 IP 的价值在这里同样成立：流媒体平台对机房 IP 的判定比住宅 IP 严格得多。

> 4K 需要 20–25 Mbps，B 方向做不到。**这不是配置问题，是链路容量问题。**

### 4. 需要住宅 IP 的注册 / 验证（B 方向）

**这是 B 方向真正的用途，而且几乎不消耗带宽**——注册和验证都是文本级请求。

判断一个 IP 好不好，看四个数（实测工具：任何一个 IP 风险检测站）：

| 指标 | 我们的实测值 |
| --- | --- |
| IP 属性 | **家庭住宅 IP (ISP)** |
| ASN / 运营商 | <ASN> 某住宅ISP Communications |
| VPN / 代理 / Tor 检测 | **全部未检测到** |
| 滥用记录 | **无** |

**光有干净 IP 不够，还要环境一致。** 实测过的四层：

| 层 | 状态 | 说明 |
| --- | --- | --- |
| IP | ✅ 统一 | 浏览器出口 = 住宅 IP |
| DNS | ✅ 统一 | 走出口那台的 ISP DNS，不是本地 DNS |
| WebRTC | ⚠️ 未解决 | 见坑 10：TUN 模式下浏览器参数管不到 |
| 时区 / 语言 | ⚠️ 未处理 | 系统时区仍是本地，对风控的实际权重未知 |

> **DNS 统一是怎么做到的**：把浏览器**整个**绑到一条固定出口的端口（见 [outbound.md](outbound.md) 的端口矩阵），
> 而不是让它走规则表。规则表下 DNS 仍会走本地，绑端口之后 DNS 跟着出口走。

### 5. 远端执行命令 / 当探针（两个方向都行）

链路上那台机器可以被当成一台「在那个国家里的电脑」：

- 查当地价格、库存、活动（比从外面查准，因为看到的是本地价）
- 测某个服务在当地的真实可用性和延迟
- 跑定时任务、抓数据，只回传结果

**几乎不吃带宽**——回传的是文本。

前提：自己配一对密钥，别用密码。

### 6. 借用对端算力（B 方向）

B 方向那台机器实测：**下行 342 Mbps，上行 22 Mbps**。

所以：**大东西在那边处理，只把结果传回来。**

- 批量下载 / 转码 / 压缩，只回传成品
- 跑脚本抓数据，只回传汇总

8 Mbps 传结果够用，传原始数据会卡死。**输入大、输出小的活，才是它的用法。**

### 7. 互备（两个方向同时开的时候）

两台机器互为出口，天然是两条链路：

- A 方向的隧道挂了 → B 方向那条还在
- 反过来也一样

**注意：它们共享同一对物理链路**，所以「互备」备的是**软件层故障**（进程挂了、配置错了），
不是「对端断网」。

## 不能做的

| 想干的事 | 为什么不行 |
| --- | --- |
| **4K 视频** | B 方向满额 7.5 Mbps，需要 20–25 |
| **在线游戏** | RTT 225–320 ms，物理上不可能 |
| **大文件备份 / NAS 同步** | 1 TB 在 7.5 Mbps 下要跑 30 小时以上 |
| **多人共用** | 7.5 Mbps 分给两个人都不够；而且线路和账号挂在对方名下 |
| **7×24 可靠性** | 对端关机 / 睡眠 / Windows 更新重启就断。实测撞过一次，断了 2.5 小时 |

---

## 一个容易被忽略的「不能」

**别把住宅 IP 当免风控通行证。**

同一个出口 IP 上挂多个账号、短时间高频请求、多设备并发——**银行侧一样会盯**。
住宅 IP 解决的是「IP 类型」这一层，解决不了行为层。

真正降低风险的顺序是：

1. 出口 IP 类型（住宅，已解决）
2. 环境一致性（DNS 已解决，时区未解决）
3. **行为本身**（这条只能靠自己）
