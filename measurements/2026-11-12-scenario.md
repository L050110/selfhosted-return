## 一、结论先放这

| 路径 | 吞吐 | 说明 |
| --- | --- | --- |
| 旧方案 gost（TCP 转发） | **0.14 Mbps** | 昨夜状态。320 ms RTT + 5–13% 随机丢包下 TCP 彻底塌掉 |
| 新方案 hysteria2，直连 SOCKS 1081 | **14.92 Mbps** | 106 倍 |
| 新方案 hysteria2，经 Clash 7890 | **15.09 Mbps** | 7890 被钉死到「对端」这一个节点 |
| 新方案，经 Clash 7897（规则模式） | 2.11 Mbps | **不是隧道的问题**，见下面第三节 |

出口 IP 全程是 `<对端出口IP>`（某住宅ISP，洛杉矶 某市），两端一致。

```powershell
# 出口 IP
curl.exe -s -x http://127.0.0.1:7890 https://ipinfo.io/json
curl.exe -s --socks5-hostname 127.0.0.1:1081 https://ipinfo.io/json
```

## 二、10 MB 实流下载 + 到 claude.ai 的时延

```
http=200  time=5.492243s  speed=1820751 B/s   → 14.57 Mbps
```

到 `claude.ai` 的握手（经 7890，出口是对端家宽）：

```
try1 : connect=0.000875s  tls=0.387440s  ttfb=0.709009s  code=403
try2 : connect=0.000901s  tls=0.381186s  ttfb=0.699082s  code=403
try3 : connect=0.000956s  tls=0.364310s  ttfb=0.683804s  code=403
```

- `connect` 是到本地代理的时间（千分之一秒量级，正常）
- `tls` 0.38 s ≈ 一个多来回 —— **这就是 320 ms RTT 的物理代价**，软件优化不掉
- `ttfb` 0.70 s = TLS 1.3（1 RTT）+ 应用层首个字节
- `403` 是没带 Cookie 的预期结果，不代表链路有问题

> 别拿 `api.anthropic.com` 当测速目标。它会被判成异常流量，
> 而且如果规则把它导向机场节点，测出来的根本不是这条隧道。

## 三、为什么 7897 只有 2.11 Mbps

7897 是 mixed-port，**走规则**。测速目标 `speed.cloudflare.com` 命中的是
`RuleSet:geolocation-!cn` → 机场节点，不是对端家宽。所以那个数字测的是机场。

7890 在合并配置里被显式绑定到对端节点，**不走规则**，所以它才等于隧道的真实速度。

要验证某个程序实际走哪条路，别猜，读 mihomo 的连接表：

```powershell
.\scripts\clashpipe.ps1 -Path '/connections' -OutFile conns.json
# metadata.process / chains / rule / rulePayload 四个字段就够了
```

当晚实测，Claude Desktop 的三条活动连接：

| host | chains | rule |
| --- | --- | --- |
| `claude.ai` | `对端节点 > Claude` | `ProcessName:Claude.exe` |
| `bridge.claudeusercontent.com` | `对端节点 > Claude` | `ProcessName:Claude.exe` |
| `nexus-websocket-a.intercom.io` | `对端节点 > Claude` | `ProcessName:Claude.exe` |

三条都落在对端节点上，没走机场。这才叫「验证过」。

## 四、改造前后对端的进程变化

| | 之前 | 之后 |
| --- | --- | --- |
| 对端监听 | gost，TCP `:1080` | hysteria2，**UDP** `:9443` |
| 本端 | fwd.js 转发到 gost | hysteria 客户端，本地 SOCKS5 `127.0.0.1:1081` |
| 存活方式 | 手动 / SSH 会话内 | 计划任务（`AtLogOn` + 每 5 分钟） |
| 抗丢包 | TCP 重传，塌 | QUIC + Brutal 固定速率补发 |

## 五、这次改造中新踩到的坑

写进 `docs/pitfalls.md` 的：

- **坑 6（已修正）**：`hysteria cert` 在 v2.13.0 **不吃任何参数**，
  `hysteria cert --host hysteria.local` 直接 `FATAL cert command does not accept arguments`。
  证书 CN 取的是机器名（取的是对端机器名），客户端 `sni` 必须跟着机器名走。
  **本文档旧版本写的 `--host` 用法是错的，已改掉。**
- **坑 7**：防火墙里一条指名的 `Block` 规则会压过 `Allow`，且不报错 ——
  表现为「端口在听、服务端日志空白、客户端一直 timeout」
- **坑 8**：SSH 里起的子进程会随会话结束一起死，`conhost --headless` 也救不了 —— 只能用计划任务
- **坑 9**：用 TCP 探 9443 会得到假阴性 —— 那是 UDP/QUIC 端口，TCP 连不上才是正常的

另有两条只在写脚本时才碰到的：

- **hysteria2 的内置 SOCKS5 不做认证**。Clash 那边如果给这个 proxy 填了
  `username`/`password`，连接会被拒，表现为「端口通但代理不通」。
- **PowerShell 5.1 的 `-match` 作用在字符串数组上时只做过滤，不会设置 `$Matches`**。
  于是 `$Matches` 会**残留上一次匹配的结果** —— 写 `verify.ps1` 时它把端口 `1081`
  当成了出口 IP。要么先 `-join` 成单个字符串，要么用 `[regex]::Match()`。
